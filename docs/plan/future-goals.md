# ErgoAgent 后续目标

本文档记录当前版本已知问题、尚未完成的能力和后续验收目标。它是后续迭代的目标清单，不代表所有目标都已完成。

## 本次反馈（2026-09-04）

- 查看标注视频时，人员标注框和姿态标记线条过细，实际画面中几乎不可见。
- 标注视频播放和分析预览不够流畅，用户感受到明显跳帧或更新延迟。
- 分析过程中网页只显示少量识别帧，无法连续理解模型正在处理的画面。

后续实现必须先复现上述问题，再分别验证标注可见性、最终视频播放和分析过程预览；不能用单纯的 CSS 动画或伪造百分比代替真实分析状态。

2026-09-04 已完成代码侧改进：标注绘制增强、缩放后的原子预览、真实帧号轮询、H.264 `faststart` 播放和逐帧定位。目标浏览器中的长视频连续播放、不同分辨率截图和色觉可访问性仍待人工验收。

## 当前已知问题

### 1. 标注框和姿态标记可见性不足

- 当前标注框线宽较细，在高分辨率视频和浅色背景中不易辨认。
- 关键点、骨架线、人员框和 REBA 文本之间缺少统一的视觉层级。
- 不同风险等级的颜色对比还不够稳定，部分画面需要放大后才能确认标注。

目标：在 1080p、4K 和移动端缩放场景下，人员框、关键点、骨架和 REBA 标签均清晰可见；高风险状态具备足够的颜色、描边和背景对比，并通过色觉可访问性检查。验收时需保留不同分辨率的截图，确认框线、关键点和文字不会因缩放失去辨识度。

### 2. 标注视频播放不够流畅

- 当前分析阶段的预览通过周期性写入 JPEG，再由网页轮询刷新，不是连续视频流。
- 页面轮询间隔、磁盘写入和图像解码会造成跳帧或更新延迟。
- 当前识别流程是离线处理，无法保证网页展示帧率与原视频帧率一致。

目标：区分“分析进度预览”和“最终标注视频播放”两个场景。最终视频应稳定支持播放、暂停、拖动、逐帧定位和音视频元数据读取；分析中预览应明确显示采样率与延迟，不让用户误以为页面正在播放完整实时视频。验收目标为：常用浏览器中连续播放无持续卡顿，播放控件可读取时长并支持拖动，首帧和后续帧加载失败时有明确提示。

### 3. 网页只看到少量识别帧

- 当前进度预览只在每若干帧保存一张图片，前端也按固定间隔请求，因此只能看到抽样帧。
- 页面目前展示的是“最近一次可用标注帧”，不是完整识别过程回放。
- 当任务很快完成或浏览器请求错过写入时，用户可能看不到有效预览。

目标：提供可解释的分析过程可视化，包括当前帧、总帧数、已检测帧、处理阶段、采样频率和更新时间；必要时增加低码率分析中视频流或环形帧缓存。展示必须来自真实 Worker 输出，不使用伪造百分比或模拟状态。验收时要能连续看到一段可理解的识别过程，并能解释“原视频帧率、处理帧率、网页刷新率”三者差异。

## 尚未完成的核心能力

### 视觉模型与跟踪

- 三维姿态估计尚未接入，当前只有 MediaPipe Pose 二维关键点。
- 成熟的多人姿态检测、身份关联和遮挡恢复尚未完成；OpenCV HOG 多人模式仍是实验开关。
- 人员轨迹在交叉、遮挡、快速移动和多人同时出现时需要系统性评测。
- 需要补充不同摄像机角度、光照、服装、作业姿态和视频编码的测试集与质量指标。

验收目标：明确支持的场景边界，报告检测率、关键点置信度、轨迹连续性、ID 切换和失败原因，并对不满足质量门槛的结果明确告警。

### REBA 与职业工效评估

- 当前 `reba-standard-proxy-0.2` 对视频不可观测的负荷、耦合、扭转和活动频率使用中性代理值。
- 尚未完成完整的人工输入、专家复核和可编辑 REBA 表单。
- 风险事件的重复次数、持续时间和身体部位聚合仍是简化实现。
- REBAPose、AutoPostureCV 等候选基线尚未集成，也没有同视频可复现比较结果。

验收目标：把自动推断、视频不可观测项和人工填写项明确分开；每个分数能追溯到规则、输入和证据帧；正式报告明确标注“辅助评估”边界。

### 结果、报告与交互

- 结果工作台仍缺少完整的时间轴、逐帧浏览、原始视频与标注视频同步对照。
- 风险事件和证据帧的筛选、排序、批量导出及复核状态尚未完善。
- 结果按钮、报告入口、下载和新窗口播放等交互需要统一状态反馈和错误处理。
- 分析失败、取消、重试、重复上传和长任务恢复需要更完整的端到端测试。

验收目标：用户可以从任务进入结果、定位事件、查看证据、回看标注视频、导出报告并记录复核结论；每个操作都有明确的加载、空状态、失败和成功状态。

### AI、模型和外部 API

- 当前真正执行视觉分析的是本地 MediaPipe Pose；REBA 是本地规则计算，不是外部大模型。
- Evidence Assistant 目前是基于已保存事实的确定性查询与文本组合，不接入 GPT、Claude 等通用大模型。
- 尚未完成训练好的姿态模型、专用动作分类模型或云端推理 API 的选型、评测和接入。
- 尚未建立外部 API 的密钥管理、成本限制、超时重试、脱敏、审计和服务降级方案。

后续原则：外部 LLM/API 只用于受证据约束的报告润色、问答和整改建议，不能替代姿态检测或 REBA 规则评分。涉及人员和现场视频时，优先本地部署、脱敏传输和明确授权。

### 工程化与部署

- 当前主要面向本机单用户，尚未完成账号、权限、审计日志和公网部署安全边界。
- SQLite 和逐帧 JSON 存储尚未经过长视频、高并发和大规模结果的容量评测。
- 数据保留策略目前只有配置项，自动清理、备份和恢复流程尚未完成。
- 缺少统一的 CI、浏览器自动化回归、性能基准和跨平台启动验证。

验收目标：完成安全模型、数据生命周期、部署方式、性能上限和故障恢复文档，并通过持续集成和浏览器端到端测试。

## 优先级建议

1. 先解决标注可见性、最终视频流畅播放和分析中预览表达，避免用户误判识别是否正常。
2. 再完善时间轴、逐帧复核、失败恢复和报告交互，形成可用的证据闭环。
3. 接着评测多人/三维模型和完整 REBA 输入，建立可量化的模型质量门槛。
4. 最后按合规和成本要求接入训练模型或外部 API，并补齐部署安全与运维能力。

## 完成定义

- 所有已知问题都有复现步骤、性能指标和回归测试。
- 页面静态截图清晰，标注视频可连续播放，移动端无溢出或遮挡。
- 分析过程展示真实数据，能解释采样与延迟，不展示虚假进度。
- 每条风险结论都能追溯到模型版本、规则版本、输入项和证据帧。
- 文档、模型许可、API 使用范围、数据处理方式和启动方式保持同步。
