# ErgoAgent 2026 全局规划和可行性评估

评估日期：2026 年 8 月 29 日

## 一句话目标

在不自采数据、不依赖硬件、第一阶段不训练大型模型的条件下，完成“公开作业视频到人员级连续工效风险和证据解释”的可运行软件，并用同一核心系统适配 iCAN 创新赛道和 AI 应用创新挑战赛软件赛道。

## 可行性结论

总体判断：可行，但属于“工程可行、规则和资料仍需核验”的项目。

| 维度 | 判断 | 依据 | 主要风险 |
| --- | --- | --- | --- |
| 主题与比赛匹配 | 高 | 纯软件、行业场景、可运行演示、Agent 协同均有对应赛道要求 | 创新赛道全国和地方规则可能不同 |
| 基础算法 | 中高 | REBAPose、MotionBERT 等有公开实现和权重线索 | 依赖版本、权重入口、真实视频稳定性 |
| 数据 | 中 | 有施工和姿态数据候选，且可以先做推理 | 数据许可、申请流程、场景分布与目标不完全一致 |
| 原创空间 | 中高 | 连续风险、证据链、工具约束 Agent 尚未作为本项目实现 | 不能把已有工作包装成首创 |
| 本科生完成概率 | 中高 | 第一阶段可以不训练，模块可以逐步交付 | 多人员跟踪、三维姿态和前端同时推进会失控 |
| 比赛演示效果 | 高 | 视频骨架、风险时间轴、证据帧和问答闭环可直观展示 | 处理速度和演示视频稳定性需要优化 |
| 商业和应用价值 | 中高 | 建筑、制造、仓储、物流有明确职业健康场景 | 需要避免医疗诊断或安全监管过度宣传 |

## 范围锁定

### 必做

1. 公开视频输入。
2. 人员检测、跨帧 Worker ID 和姿态结果。
3. 关节角度、REBA 规则和置信度。
4. 风险事件聚合、时间段定位和证据帧。
5. JSON 结果和带标注视频。
6. 最小 Web 展示。
7. Agent 工具调用和有证据的解释。
8. 中文开发日志、实验记录、许可证记录和比赛材料索引。

### 暂不做

1. 硬件和传感器。
2. 自建数据集。
3. 从头训练姿态大模型或大型视觉语言模型。
4. 多 Agent 编排、数字孪生、AR 和手机端。
5. 与职业工效无关的安全帽、火灾、吸烟和跌倒检测。

## 阶段和出口条件

### 阶段零，规则和资料核验

产物：官方通知存档、赛道和材料清单、开源资料表、许可证表、数据下载记录。

出口条件：每条比赛硬性要求都有来源或明确的待确认人和日期；主线依赖没有许可证黑洞。

### 阶段一，感知基线

产物：REBAPose 图片推理、公开视频推理、逐帧 JSON、带骨架视频、运行日志。

出口条件：至少一个公开样例完成从输入到输出，失败输入有明确错误，不输出伪造结果。

### 阶段二，基线比较和统一契约

产物：REBAPose 与 AutoPostureCV 在同一视频上的比较，统一结果格式，模型和规则版本记录。

出口条件：能量化比较关节角稳定性、风险分数、处理速度、遮挡和多人员表现。

### 阶段三，原创时序风险

产物：RiskEvent、持续时间、峰值和平均分、重复频率、置信度加权、失败案例。

出口条件：参数有来源，规则可解释，至少有基线对比和消融记录。

### 阶段四，产品闭环

产物：最小 FastAPI 接口、前端分析页、结果时间轴、证据帧跳转和报告导出。

出口条件：用户能完成上传、分析、查看风险、打开证据和导出结果的完整路径。

### 阶段五，Pose grounded Agent

产物：工具协议、工具调用日志、规则检索、用户追问闭环和不确定性提示。

出口条件：每个关键回答都能列出工具、输入、证据和规则；模型不可用时核心分析仍可运行。

### 阶段六，比赛交付

产物：创新赛道版本、AI 挑战赛版本、演示视频、应用方案、源码包、运行说明和原创证据链。

出口条件：按当届官方要求完成提交检查，并由未参与开发的人按运行说明复现一次。

## 技术验证计划

1. 先验证 REBAPose 当前权重和依赖，不先重训。
2. 以公开施工图片和公开视频建立小型固定回归样例，记录输入校验值。
3. 对远距离、遮挡、侧身、多人员和时序抖动分别记录失败率和人工观察。
4. 若三维模型入口或显存不稳定，先以二维角度和离线视频完成演示，不让 CP3D 阻塞主线。
5. 若现成姿态模型不足，再考虑 RTMPose 或 MotionBERT Lite 的局部替换，先做架构决策记录。

## 资源估计

第一阶段以有八到十二 GB 显存的单卡或 CPU 加速环境为目标，使用小样例和离线处理。CP3D README 提到的两张 A5000 是其开发环境，不是本项目第一阶段的硬性配置。大模型优先使用远程接口或小型本地模型，并把密钥放在环境变量中。

## 主要风险和应对

1. 规则风险：以官网和组委会通知为准，保存原文和核验日期。
2. 许可证风险：许可证不明的资料只做内部研究，不进入发布包。
3. 数据风险：不自采，不把受限数据上传到第三方服务，先核验再展示。
4. 算法风险：把不确定性展示给用户，不在遮挡严重时输出确定诊断。
5. 工程风险：按垂直切片交付，任何阶段失败都保留可运行的较小版本。
6. 原创风险：维护提交历史、实验记录、参数来源和第三方归属，避免换皮复刻。
7. 医疗和安全表述风险：统一使用“辅助评估”和“风险提示”，明确不能替代专业人员判断。

## 评估结论

ErgoAgent 值得继续投入。最可靠的路线是先做可运行基线，再用连续风险和证据链建立原创，再把 Agent 放在可靠工具之上。项目能否冲击高奖取决于真实运行稳定性、原创实验和演示完成度，不取决于堆叠更多模型名称。

## 执行计划

以下按相对周次安排，实际日期以赛事最终通知、设备和资料获取情况为准。每周结束时都要更新 `docs/records/changes.md`、`docs/records/issues.md` 和架构快照。

### 第零周，冻结边界和环境

目标：不让资料搜索无限扩张。

交付：架构规格入口、公开资料和许可证清单、固定样例目录、环境记录、运行日志模板。

停止条件：规则或许可证存在未解决的高风险时，不把对应资料接入主线。

### 第一周，跑通感知基线

目标：完成 REBAPose 图片和视频推理。

交付：单条图片命令、单条视频命令、逐帧 JSON、带骨架视频、失败输入处理。

通过条件：同一输入重复运行，结果结构稳定，能够记录模型版本和处理耗时。

### 第二周，统一结果和基线比较

目标：固定数据契约，并在同一视频上比较 REBAPose 与 AutoPostureCV。

交付：结果转换器、输入校验、比较脚本、实验表、遮挡和多人失败样例。

通过条件：可以解释主线为什么保留或替换某个组件，不以星数或宣传语代替证据。

### 第三周，跟踪和连续风险

目标：建立 Worker ID、风险事件和置信度感知评分。

交付：跨帧跟踪、事件聚合器、参数配置、事件证据帧、规则和基线对比。

通过条件：风险事件有起止时间、峰值、平均值、重复次数、身体部位和不确定性。

### 第四周，最小产品闭环

目标：让用户完成上传、等待、查看、定位证据和导出报告。

交付：本地服务、分析任务状态、结果页面、时间轴、错误状态和报告文件。

通过条件：新环境按照运行说明可以启动，并完成一次完整用户路径。

### 第五周，接入受约束 Agent

目标：让 Agent 成为可靠分析工具的编排和解释层。

交付：工具协议、调用日志、规则检索、证据引用、追问处理和模型不可用时的降级行为。

通过条件：关键回答中的每个数字都能在结构化结果和证据帧中找到来源。

### 第六周及以后，比赛交付和持续改进

目标：形成两个赛道版本，同时保持主线代码一致。

交付：应用方案、演示视频、源码包、运行说明、许可证附件、原创开发证据和复现记录。

通过条件：由未参与实现的人按文档完成复现，演示视频展示请求、分析、工具协同、反馈和追问闭环。

## 当前报名周期的压缩执行路径

如果仍处于 2026 年创新赛道材料提交前，优先交付阶段一的可运行视频演示、技术路线和原创开发记录，暂缓 Agent 和复杂前端。随后利用 AI 应用挑战赛截止前的时间完成阶段三至阶段五。任何无法在截止前验证的能力都应从材料中删去，不用概念承诺替代运行证据。

## 每个里程碑的固定检查

1. 代码是否能在干净环境运行。
2. 输入、输出、模型、规则、数据和许可证是否有记录。
3. 是否有至少一个失败样例和处理方式。
4. 是否需要更新架构、决策或问题记录。
5. 是否需要为确定性逻辑补测试。
6. 是否能为比赛材料提供真实截图、视频或日志。
