# 2026-08-30 基线、跟踪和 Agent 验证记录

## 当前基线

固定参考基线为 MediaPipe Pose 0.10.21（Apache-2.0），规则为 `reba-standard-proxy-0.2`。对输入视频、运行 ID、帧数、检测帧数、峰值 REBA、平均置信度和规则版本的记录由 `/api/analysis-runs/{run_id}/baseline` 返回。规则使用 REBA 表 A/B/C，但视频不可观测的负荷、耦合、扭转和活动频率会以中性值显式记录。

REBAPose 和 AutoPostureCV 已登记为候选基线，但由于权重入口、依赖和版本尚未在本环境完成核验，接口明确返回 `not_integrated`，不制造比较指标。2026-08-30 通过 GitHub API 核验到两者默认分支均为 `main`、仓库许可证元数据均为 MIT；浅克隆因当前网络环境超时，仍未完成本地入口、权重和依赖复现，因此不能形成同视频对比指标。

## 跟踪

新增 `CentroidTracker`，以检测框中心点和最大距离分配稳定的 `person-N` ID，并接入 OpenCV HOG 多人候选框实验模式。默认 MediaPipe 路径仍输出单人姿态；HOG 模式会分别裁剪候选框送入姿态模型，并把候选框置信度写入逐帧边界框。真实 4K 默认回归为 284 帧、252 帧检测、1 个 Worker；HOG 实验可生成多个 Worker，但当前视频上的候选框仍会碎片化（22 个 Worker、平均置信度 0.745），因此只作为实验开关，不能宣称多人身份稳定。多人遮挡/交叉回归视频仍待补充。

## 证据报告

每个成功运行生成 `report.html` 和 `report.json` 两个独立 artifact，均记录相对路径、SHA256、大小和 MIME 类型，并通过 artifact 内容接口下载。报告包含模型、规则、摘要、风险事件和限制说明；输入文件名经过 HTML 转义。报告只引用数据库和结果 JSON 中的事实，不能替代原始视频复核。

## 证据助手

`POST /api/analysis-runs/{run_id}/assistant` 使用确定性的工具选择和数据库事实回答“为什么风险高”“查看证据”“关节角度”等问题，并返回工具调用和引用。MVP 不调用外部大模型，因此不会在模型不可用时伪造解释；后续可将同一工具协议接入本地或远程语言模型。
