# ErgoAgent 架构快照

最后更新：2026 年 8 月 29 日

## 当前状态

仓库当前只有项目协作说明和技能文件，业务代码尚未实现。以下架构是已确认的目标架构和第一阶段实现边界，不代表功能已经完成。

## 产品目标

把公开作业视频转化为可追溯的职业工效风险信息，输出人员级风险、时间段、关键关节、置信度、REBA 规则证据和整改建议。产品名称暂定“工安智评”，技术名称为 ErgoAgent。

## 目标数据流

```text
视频或图片
  ↓
人员检测
  ↓
跨帧跟踪，生成 Worker ID
  ↓
二维姿态估计
  ↓
三维姿态或运动表示
  ↓
关节角度和 REBA 规则
  ↓
置信度感知的连续风险事件
  ↓
证据链和结构化报告
  ↓
Web 展示与受约束的 Agent 工具调用
```

## 模块边界

### 感知层

负责人员检测、姿态估计、三维提升和跟踪。感知层不得输出没有置信度的关键点，也不得直接生成自然语言结论。

### 规则层

负责角度计算、REBA 或 RULA 规则、风险等级和参数来源。规则层的输出必须包含规则版本和输入证据。

### 时序层

负责把逐帧风险聚合为风险事件，计算持续时间、峰值、平均分、重复频率、身体部位和置信度。第一版使用可解释规则，模型训练是后续可选项。

### 证据层

负责把人员、时间、关节、角度、置信度、规则和帧号关联起来。Agent 只能读取证据层提供的结构化结果。

### Agent 层

负责理解用户问题、选择工具、检索规则和组织解释。Agent 不直接替代姿态估计和 REBA 计算。

### 展示层

第一版展示结果视频、人员风险摘要、风险时间轴、证据帧和结构化报告。前端不自行计算风险。

## 统一结果契约

```text
Video
 └── Worker
      └── Frame
           ├── bbox
           ├── pose_2d
           ├── pose_3d
           ├── confidence
           ├── angles
           ├── reba
           ├── rula
           └── timestamp

Worker
 ├── RiskEvent
 │    ├── start
 │    ├── end
 │    ├── peak_score
 │    ├── mean_score
 │    ├── body_region
 │    ├── repetition_count
 │    ├── evidence_frames
 │    └── confidence
 └── Summary
      ├── exposure
      ├── repetitions
      └── risk_level
```

字段名称在接口稳定前可以调整，但必须同步变更记录和测试。任何结果都要标记输入来源、模型版本、规则版本和生成时间。

## 目标运行方式

第一阶段采用模块化单体。FastAPI 负责 REST JSON 接口和任务编排，独立 Python Worker 负责图片和视频分析，React 与 Vite 负责结果工作台。SQLite 保存任务与元数据，本地文件系统保存视频、结果视频、证据帧和报告，Docker Compose 负责本地复现。API 请求不得执行 GPU 推理。

## 外部组件边界

推荐先核验并按许可证使用：REBAPose、MotionBERT、MMPose、ByteTrack、AutoPostureCV 和公开的 REBA 规则实现。任何组件接入前记录仓库提交号、许可证、权重来源和本项目改动，不能把第三方结果冒充原创。

## 架构验收

架构实现后必须能回答：一个风险结论来自哪个 Worker、哪个时间段、哪一帧、哪些角度、哪条规则和哪个模型版本。无法回答时，视为证据链不完整，不进入比赛材料制作。
